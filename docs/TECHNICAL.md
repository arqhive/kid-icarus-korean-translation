# 한글화 기술 문서

## 입력과 출력

대상은 GBA 패미컴 미니 24 일본판(`FPTJ`) 4 MiB ROM입니다. 전체 SHA-256으로 입력을 제한합니다.
NES/FDS 게임과 이를 실행하는 GBA 래퍼가 들어 있어서 두 표시 계층을 각각 수정합니다.
최종 결과는 원본과 같은 4 MiB이며 원본 대비 IPS로 배포합니다. 원본 파일은 수정하지 않습니다.

## 재현 파이프라인

`tools/paths.py`가 루트·입력·폰트·로고·출력 경로를 정합니다. `tools/build.py`는 다음 단계를 별도 프로세스로 실행합니다.

1. `analyze_rom.py`: 원본의 게임 데이터와 GBA 엔진을 사용자 정의 LZ 방식으로 해제합니다.
2. `build_logo_v2.py`: 한국어 로고 소스를 160×64로 변환하고 기존 타이틀 타일·색상 제약에 맞게 삽입합니다.
3. `build_text_patch.py`: 게임 텍스트, 글리프 뱅크, 표시 코드를 넣고 흔들림을 보정합니다.
4. `audit_kana.py`: 래퍼 메시지 포인터 59개와 가나를 포함한 블록 47개를 추출합니다. 원문·그림은 `work/`에만 기록합니다.
5. `build_text_v3.py`: 공통 메시지·폰트를 재배치하고 GBA 엔진의 폰트 전송 주소를 수정합니다.

내부 `v2`·`v3` 파일명은 단계 구분용입니다. 최종 파일명과 패키지는 `VERSION`의 `v0.1`을 사용합니다.
`work/legacy/`에 의존하지 않습니다. 의존성 버전은 `requirements.txt`에 고정했습니다.

## 주요 위치

| 위치 | 용도 |
|---|---|
| ROM `0x2AE0` | 압축된 게임 데이터, 해제 크기 108,472바이트 |
| 원본 ROM `0x17380` | 압축된 GBA 엔진, 해제 크기 `0x824C` |
| ROM `0x128` | GBA 엔진 압축 데이터 포인터 |
| ROM `0x17D0` | 공통 메뉴 글자 타일·팔레트 조회표 |
| ROM `0x27CC + id×8` | 메시지 위치·창 크기·스크립트 포인터 |
| ROM `0x1C200` | 새 공통 메뉴 폰트 `0x900`바이트와 번역 메시지. 원본의 채움 영역 |
| 엔진 내부 `0x4E0` | 폰트 DMA 설명자 |

원본 `0x1C200` 이후는 게임이 참조하지 않는 채움 데이터라 여기에 새 폰트와 메시지를 넣습니다.
재압축한 엔진(18,795바이트)은 원래 자리 `0x17380`(원본 18,889바이트)에 넣어 `0x128` 포인터를 원본 값으로 유지합니다.
원래 일본어 공통 메시지 본문 `0x19CC..0x27CB`는 참조를 바꾼 뒤 `FF`로 지웁니다.
GBA 헤더 영역은 유지합니다.

## 게임 글꼴과 흔들림

게임 글꼴은 갈무리7을 바탕으로 한글 125종을 18개 문맥별 뱅크에 배치합니다.
NES 쪽 사용하지 않는 BIOS 영역에 뱅크 전환 코드를 배치합니다.
래퍼의 축소 표시에서 번갈아 선택되는 CHR 행 1/2와 5/6을 동일하게 만들어 시간에 따른 글자 모양 변화를 없앴습니다.
타이틀은 승인된 로고의 한 위상을 유지해 같은 행 보정을 적용합니다.
신전 대사 0·3은 원문의 이름 삽입 제어 코드(`FD 08 20 01`, RAM `$0120`의 8글자)를 첫 줄 뒤에 유지합니다.

## 공통 메뉴 글꼴

글자 155개(한글 124개, 공백 제외)를 4bpp 타일의 세 비트 평면에 나눠 담고 팔레트로 선택합니다.
프레임·커서가 직접 참조하는 타일은 보존합니다. 글자 조회표는 254개 엔트리를 수정합니다.
폰트 DMA 소스는 VRAM 내 원본 리소스에서 ROM `0x1C200`의 새 폰트로 바꿉니다.
예/아니요·1P/2P/취소는 선택 강조 제어 코드를 유지하는 별도 인코더를 사용합니다.

## 검증 범위

빌드에서 압축 왕복, 글자 수·뱅크 한도, 창 경계, IPS 왕복을 검사합니다.
`verify_text_v3.py`는 최종 ROM에서 47개 번역 메시지를 다시 해석하고 모든 글리프와 좌표를 확인합니다.
mGBA libretro로 새 부팅·메뉴·계속·리셋과 메뉴 120프레임 안정성을 확인하고 결과를 `work/build/final/verification.json`에 남깁니다.

파일에 원래 가나 글꼴 비트맵 29개가 남아 있지만, 파악한 번역 표시 경로에서는 뱅크 글꼴로 대체됩니다.
정적 검사 결과를 모든 실행 경로·전체 플레이 검증으로 해석하지 않습니다. 통신·저장 오류 조건 대부분은 정적 검증만 했습니다.
원본과 비교용 스크린샷, 메모리 덤프, 원문은 Git 관리 대상이 아닙니다.

## 배포와 바탕화면 복사

`make_patch.py`는 현재 빌드의 원본 해시·결과 해시·IPS 왕복을 확인하고 고정 순서와 ZIP 타임스탬프로 패키징합니다.
사용자용 `apply_patch.py`는 Python 표준 라이브러리만 사용하며 원본·패치·결과 SHA-256을 검사합니다.
`rom_delivery.py`는 Windows의 실제 바탕화면 레지스트리 설정을 읽고 결과를 복사한 뒤 SHA-256을 비교합니다.
각 빌드의 ROM·확인값은 `work/`에도 유지합니다.
